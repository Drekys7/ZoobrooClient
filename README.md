# ZooBroo Client

Самостоятельная карта для посетителей зоопарка. React + TypeScript + Leaflet; статический сайт, без редактора, авторизации и базы черновиков.

## Запуск

Требуется Node.js 22+.

```sh
npm ci
npm run dev
```

Карта разработки: http://127.0.0.1:5174/. Для проверки производительности с телефона в той же локальной сети выполните `npm run build`, затем `npm run preview:lan` и откройте адрес Network, который напечатает сервер (порт 4174). Компьютер должен оставаться включённым, а сервер — запущенным.

```sh
npm test
npm run build
npm run preview
```

Готовый сайт находится в `dist/`; его можно разместить на обычном статическом хостинге, Firebase Hosting или сервере зоопарка. `firebase.json` содержит настройки файлов и кеширования, но Firebase-проект и публичный домен пока не подключены. Для встраивания используйте iframe с высотой, заданной сайтом зоопарка. Размещайте приложение на URL с завершающим `/`.

## Перенесённый снимок

Источник — **сохранённый** `ZooBrooAdmin/public/startup-template.json`, с учётом текущего кода публикации админки. 41 точка, 15 участников групп, 8 категорий, 6 зон, 106 медиафайлов; немецкий и английский. В сохранённом снимке нет мероприятий; панель расписания поддерживается и показывает пустое состояние.

Координаты, стили и переопределения маркеров, подписи зон, описания, факты, фотографии, атрибуции и переводы сохранены. Компоненты поиска, карточек, групп, расписания и CSS перенесены из симулятора. Рамка имитируемого телефона удалена: карта занимает реальный экран. Анимации карточек используют transform/opacity; поддержаны safe-area и reduced-motion. На компьютере доступны кнопки масштаба, на телефоне — pinch-to-zoom.

Нижняя правая кнопка приближает камеру к стрелке на дорожке перед главным входом (масштаб 5,3× относительно общего вида). Позиция пока фиксирована: `VISITOR_POSITION` в `src/components/visitor-location.ts`; это не GPS. Для реальной позиции посетителя понадобится геопривязка, которой ещё нет в контракте.

Поворот стрелки использует компас телефона: `webkitCompassHeading` на iOS или абсолютные показания ориентации на Android. Относительные показания гироскопа не считаются направлением на север. Датчик требует HTTPS (или localhost); на локальном HTTP-адресе телефона поворот недоступен, но стрелка и переход к ней работают. На iOS разрешение запрашивается при нажатии кнопки местоположения. Без показаний стрелка остаётся в исходном положении вверх. При встраивании в сторонний iframe сервер и iframe должны разрешать `accelerometer`, `gyroscope`, `magnetometer`. Обновление поворота не вызывает рендер карты в React.

## Обновить локальную копию из админки

```sh
npm run sync:admin
# другой путь к админке и/или сохранённому экспорту:
npm run sync:admin -- "C:/path/to/ZooBrooAdmin" "C:/path/to/startup-template.json"
```

Импорт читает админку, ничего в её проекте не меняет. Он использует её валидатор и `buildPublishedSnapshot`, выносит бинарные ресурсы из Base64 в отдельные файлы, создаёт тайлы и атомарный указатель версии. Для импорта нужны установленные зависимости админки. Сборка и работа сайта от соседнего репозитория не зависят.

Изменения, оставшиеся только в IndexedDB открытого браузера админки, не попадают в этот файл автоматически. Сначала сохраните стартовый шаблон/экспорт с ресурсами в админке, затем выполните импорт. Точный источник, контрольная сумма и дата сохранения записаны в `docs/baseline.json`.

## Производительность

- Leaflet управляет движением карты без React-обновлений на каждом кадре.
- Общий вид использует компактный JPG 1254×1254 (около 208 КБ), подготовленный из существующего малого JPG v39. Исходник v40 5016×5016 (5,65 МБ) целиком при обычном открытии не загружается.
- На приближении загружаются только нужные WebP-тайлы 512×512. Низкое разрешение остаётся под ними при медленной сети; тайлы вне экрана удаляются с небольшим запасом.
- Иконки 128×128, фотографии карточек загружаются по требованию, фоновые проверки версий — раз в 5 минут только на видимой странице, а также после возврата на вкладку и восстановления сети.
- Убраны дорогие backdrop-filter с элементов над движущейся картой; движение поднятых кнопок сделано через transform.
- Статические ресурсы имеют адреса с хешами; JSON отдельно от JS. Кеш последней исправной версии не является гарантией полной работы офлайн: для этого понадобится service worker с управлением кешем медиа.

FPS зависит от устройства, браузера и частоты экрана. Испытания на физических Android/iPhone пока не проведены; гарантии 60/120 FPS нет. Браузерная проверка и автоматические тесты описаны в `docs/verification.md`.

## Данные и будущие серверы

`src/data/map-repository.ts` — интерфейс `MapRepository` и рабочий HTTP-адаптер. UI не знает о Firebase или SQL.

```env
VITE_MAP_MANIFEST_URL=https://your-host.example/zoos/demo/manifest.json
```

Без переменной загружается комплектный `public/data/manifest.json`. Сервер должен разрешать CORS для сайта, если расположен на другом origin. Используйте HTTPS.

Контракт `PublishedZooMap` скопирован без изменений из админки в `src/public-contract/`. Manifest содержит проект, версию, URL JSON, SHA-256 и необязательные параметры доставки растровой карты. Без тайлов клиент умеет отображать обычное фоновое изображение. Неподдерживаемая схема и некорректные ссылки отклоняются. SHA-256 проверяется в secure context (HTTPS/localhost).

Новая версия становится активной после проверки JSON и загрузки карты/иконок/шрифтов. При сбое остаётся предыдущая; последняя исправная копия метаданных сохраняется локально. Переключение сервера на старую версию поддерживает rollback.

Подробности подключения Firebase и собственного API — в `docs/data-architecture.md`.
